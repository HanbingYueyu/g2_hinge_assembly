# G2 独立绝对末端轨迹示教设计

日期：2026-09-20

## 目标与范围

新增一套完全独立的单臂示教工具。它不接入双臂主流程，不读取相机，不控制夹爪，也不处理铰链、孔位或电批。

操作者使用 G2 手臂自身的拖动按钮移动左臂或右臂。程序记录机械臂原始末端
`arm_l_end_link` / `arm_r_end_link` 在 `base_link` 下的**绝对位姿轨迹**。回放前，程序必须先在本地把整条末端轨迹转换为连续的七关节轨迹并完成验证；只有已有完整且验证通过的关节轨迹文件时，回放命令才允许机器人运动。

录制和回放使用 GDK `control_mode=1` 关节位控，不使用关节阻抗、笛卡尔阻抗或力控制。录制程序本身不发送运动目标；实体拖动按钮的行为由机器人系统负责。

## 独立入口与文件

新增独立入口 `g2_adapter/cartesian_teach_trajectory_gdk.py`，提供四个子命令：

- `record`：只读记录绝对末端位姿、对应七关节角和时间戳。
- `solve`：完全离线地平滑末端轨迹并逐点求解 IK，生成关节回放文件。
- `inspect`：离线显示原始或已求解轨迹的统计信息和验证结果。
- `replay`：只接受已求解且验证通过的关节轨迹，在位控下执行；不在运动过程中临时求 IK。

新功能使用独立的数据模型、运动学模块和测试，不修改现有 `teach_trajectory_gdk.py` 的关节角示教语义。原有示教继续可用，方便对照和回退。

## 录制数据

每个采样点包含：

```text
t_ns
position_m                 # base_link 下 XYZ
orientation_xyzw           # base_link 下四元数
joint_positions_rad[7]     # 同一侧手臂的实际关节角，仅作 IK 参考与诊断
```

轨迹元数据包含：

- schema 版本、左右侧、采样频率、UTC 记录时间；
- `base_frame=base_link`；
- `tip_frame=arm_l_end_link` 或 `arm_r_end_link`；
- 七个关节名称；
- 使用的 URDF 路径及内容 SHA-256；
- 录制开始时 GDK 返回的完整关节状态映射；
- 录制开始时控制模式和机器人状态摘要。

默认 100 Hz 采样。使用单调时钟生成相对时间；末端位姿来自
`get_motion_control_status().frame_names/frame_poses`，关节角来自按名称重排后的
`get_joint_states()`。任何一项缺失、非有限、四元数模长异常或机器人状态报错时停止录制，不写出看似完整的轨迹。

程序在录制前切换并确认 `control_mode=1`，但不发送位置目标。开始和结束时均保持模式 1。按
`Ctrl+C` 或指定时长结束后原子写入 JSON。开头以首帧为基准，在平移或旋转超过配置阈值时认定开始运动，并保留运动前一帧。

## 末端轨迹处理

`solve` 首先在末端空间处理原始记录：

1. 校验时间严格递增、帧名称和左右侧一致。
2. 统一相邻四元数符号，避免 `q` 与 `-q` 引起伪跳变。
3. 对小幅位置和姿态抖动做有限窗口滤波，但不改变首末帧。
4. 按固定求解频率重采样：位置使用平滑插值，姿态使用四元数 SLERP，不对欧拉角直接插值。
5. 保留绝对 `base_link` 位姿，不根据回放起点做平移或旋转重定位。

第一版不加入路径自动缩短、空间范围裁剪或业务相关约束。重点是忠实复现录制的绝对末端轨迹。

## 本地运动学与连续 IK

当前 GDK Python 接口提供执行型末端位姿控制和运动规划，但未发现“只求解并返回关节角而不运动”的接口。因此 `solve` 使用仓库内
`robot_description/G2_t2v2_crsB_omnipicker.urdf` 建立本地正运动学和雅可比模型。

运动学链从 `base_link` 到所选 `arm_*_end_link`。只优化所选手臂七个关节；身体关节使用录制开始时的实际值固定。这样生成的是单臂轨迹，而不是全身 IK。回放前必须确认影响该链的非手臂关节仍与录制值一致，超出容差则拒绝回放，避免“绝对末端位姿相同但基座链已经变化”。

每个重采样末端点采用阻尼最小二乘迭代：

- 位置误差为三维平移差；
- 姿态误差使用 SO(3) 对数映射，不使用欧拉角差；
- 第一帧以录制的第一帧关节角为初值；
- 后续帧以上一帧 IK 解为主要初值；
- 同时用该时刻插值后的录制关节角作弱参考，稳定 7 自由度冗余关节的肘部构型；
- 每次迭代限制关节增量，并把候选解限制在 URDF 关节上下限内；
- 接近奇异点时通过阻尼抑制数值爆炸，无法收敛时整条轨迹求解失败。

求解结束后对每个关节解重新做 FK，验证它与对应末端目标的平移和旋转残差。任意点失败时不生成可回放状态。

## 整轨验证与输出

已求解文件同时保存末端目标和七关节结果，并包含以下验证报告：

- 所有点 IK 成功；
- FK 平移最大/均方误差；
- FK 姿态最大/均方误差；
- 关节限位最小余量；
- 相邻点最大关节跳变量；
- 各关节最大速度和加速度；
- 起点、终点末端误差；
- 原始轨迹文件 SHA-256、URDF SHA-256 和求解参数。

只有全部硬性检查通过时才写入 `replay_ready=true`。失败文件可以保存诊断报告，但必须标记为不可回放。默认阈值集中定义并通过命令行显式覆盖，不允许静默放宽。

本地 FK 模型还必须用当前机器人关节反馈和 GDK 当前末端位姿做一次模型一致性检查。若 URDF 计算值与 GDK 值明显不符，拒绝录制后的求解确认或回放，防止使用错误模型、错误关节零位或错误末端 frame。

## 位控回放

`replay` 的动作顺序固定为：

1. 加载已求解轨迹，验证 schema、文件哈希、左右侧、URDF 哈希及 `replay_ready`。
2. 读取机器人状态，确认无错误，并确认固定身体关节与录制状态一致。
3. 用实时关节反馈做 URDF/GDK 末端位姿一致性检查。
4. 要求显式 `--allow-motion`，切换并确认 `control_mode=1`。
5. 用 `joint_control_request()` 规划到已求解轨迹的首个七关节位置并等待实际到位。
6. 按轨迹时间以 100 Hz 调用 `move_arm_joint_servo()`，单臂只发送七个绝对关节角。
7. 周期性检查控制模式、机器人错误和反馈有效性；异常立即停止继续发送。
8. 发送末点后等待实际关节进入终点容差，再报告完成。

`--speed-scale` 只重新缩放时间，不重新求 IK。缩放后再次检查速度和加速度；超过配置上限时拒绝执行。进度按已发送的轨迹点计算，不把它描述成实际到位百分比。

回放不调用 `end_effector_pose_control()`，也不在发送过程中求解 IK。这样可以在机器人运动前发现无解、跳解、限位和速度问题。

## 边界与非目标

- 不接入 `run_bilateral_flow_gdk.py`。
- 不处理夹爪、TCP、工件、视觉或外部事件。
- 不把绝对轨迹重定向到新的起点。
- 不控制身体关节、头部或底盘。
- 不承诺关节伺服具有规划接口相同的自碰撞检查；第一版只做运动学、关节限位、速度、加速度和状态检查。
- 不删除或改变现有的关节角示教工具。

## 测试与现场验证

自动测试覆盖：数据格式、四元数处理、URDF FK/雅可比、左右臂 IK、连续选解、奇异/无解失败、限位、速度与加速度检查、哈希和模式校验，以及“未求解/验证失败的轨迹绝不发送运动”。

现场验证按以下顺序进行：

1. 只读静态录制，比较记录的 GDK 末端位姿与关节状态。
2. 对静态点和很短轨迹离线求解，检查 FK 残差及关节解是否接近录制关节角。
3. 不运动执行 `inspect`，人工查看整轨验证报告。
4. 位控下以低倍率回放几厘米的单臂轨迹。
5. 验证较长轨迹和左右臂，但始终单臂单独运行。

第一版只有完成上述小范围真机验证后，才把较长轨迹视为可用。
