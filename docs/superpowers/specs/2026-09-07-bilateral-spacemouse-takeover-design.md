# 左右手串联流程与 SpaceMouse 临时接管设计

## 目标

新增一个统一的左右手流程入口：先执行现有左手视觉流程，左手流程正常完成后等待操作者用右按钮长按 2 秒手动启动右手视觉流程。左手阶段中，右按钮长按 2 秒也会结束左手阶段并启动右手阶段。任一阶段都可以通过 SpaceMouse 双击临时接管对应手；接管不会因无操作自动释放，当前接管手再次双击时发送实测保持目标并恢复被暂停的视觉流程，双击另一手则切换接管对象。

## 已确认的按键语义

- 左按钮双击：接管左手。
- 右按钮双击：接管右手。
- 右按钮长按 2 秒：仅在左手阶段推进到右手阶段；当前接管会先安全结束。
- 左按钮松开：SpaceMouse 只产生 XYZ 平移。
- 左按钮按住：SpaceMouse 产生完整 6D 位姿。
- 右按钮单击：保留当前手的夹爪开合功能；右按钮长按不重复触发夹爪。
- 再次双击当前接管手：退出手动接管，发送实测保持目标并继续原视觉状态机。

## 约束与安全不变量

1. 任一时刻只能有一个 GDK 运动写入者；SpaceMouse 接管不启动第二个 GDK/Robot 实例。
2. 接管开始前必须停止或暂停当前末端位姿流，并以当前实测末端位姿发送保持目标；不追赶接管前的旧目标。
3. 接管期间视觉流程不消费检测结果、不发布新的自动运动目标，但保留相机、模型和状态机上下文。
4. 接管恢复时从当前实测状态继续；不重新执行左手抓取、闭爪或右手抓取前置步骤。
5. 任何 GDK 状态错误、SpaceMouse 断连、循环超时或接管恢复失败都停止后续自动动作并保持最后实测状态。
6. 右按钮长按推进阶段只允许在左手阶段生效；右手阶段不重复启动右手流程。

## 架构

### 统一阶段入口

新增 `g2_adapter/run_bilateral_workflow_gdk.py`，负责解析左右 demo 参数、创建阶段状态机，并按顺序调用现有左手与右手运行入口。阶段为 `left_auto`、`left_takeover`、`left_wait_next`、`right_auto`、`right_takeover`、`complete` 和 `failed`。左手正常完成后由左手进程保持 GDK、SpaceMouse 接管和 Web 服务，进入 `left_wait_next`；等待期间双击仍可接管左手或右手，右按钮长按才推进到右手。左手收到右长按推进事件时，先安全保持左手，再进入 `right_auto`。

### SpaceMouse 接管层

新增 `g2_adapter/spacemouse_takeover.py`，只负责 HID 读取后的按键手势、显式接管释放、接管请求和阶段推进事件。它不直接拥有 GDK；手势输出通过线程安全邮箱交给当前 demo 的唯一运动循环。

当前 demo 的运动循环接入一个 `MotionPauseGate`：自动发送路径在接管期间等待，SpaceMouse 路径使用同一个 `G2Controller` 以显式 bypass 发送 50 Hz 末端目标。接管开始和结束都由主循环确认，避免自动流与手动流同时写 GDK。

### 左右 demo 接口

为 `left_grasp_gdk.py` 和 `right_apriltag_grasp_gdk.py` 增加可选的接管邮箱/阶段回调。现有视觉状态机、相机和模型对象保持存活；在每个非阻塞运动边界检查接管事件。右侧已有的阻塞式预设/视觉锁定等待需要改为可轮询等待，以便接管请求能在 50 Hz 内被处理。

## 错误处理

- 接管请求到来时，如果当前流程正在发送一次命令，先让该命令完成，再发送实测保持目标；保持目标发送失败则终止流程。
- SpaceMouse 轴输入过期或 HID 断连时，停止手动目标发布并保持实测姿态；不自动恢复视觉流程。
- 显式释放前先发送一次实测保持目标，清空手动目标，再解除自动发送门。
- 右长按推进失败时停在左手当前实测姿态，不启动右手流程。
- 左/右 demo 任一异常返回时，统一入口进入 `failed`，不自动重启或重复抓取。

## 测试范围

- 手势状态机：左右双击、当前手再次双击释放、右按钮 2 秒长按、单击夹爪、左按钮 6D/平移映射和长按不重复夹爪。
- 接管门：接管期间自动目标不发送；恢复后继续同一个状态机阶段；接管开始/结束均以实测姿态保持。
- 阶段状态机：左手正常完成后进入右手；左阶段右长按直接进入右手；右阶段不重复推进；任一错误进入失败状态。
- 现有 `test_spacemouse*.py`、`test_control.py`、`test_safety.py` 和左右 demo 单元测试全部回归。
- 只做离线 FakeGdk/FakeRobot 验证；不在自动测试中调用真实 GDK 运动。

## 不在本次范围

- 不改变现有左右视觉检测、抓取标定、力控阈值或姿态点位。
- 不在接管后重新规划碰撞路径。
- 不增加第三个“使能键”或要求操作者持续按住才能运动。
