# G2 默认关节阻抗控制设计

日期：2026-09-19

## 目标

把项目中正式运动链路的默认控制方式从 GDK `control_mode=1` 关节位控切换为
`control_mode=3` 关节阻抗。现有运动目标、阶段顺序、视觉定位、轨迹文件和操作入口保持不变；
改变的是目标执行时使用的底层控制模式和阻抗参数。

这里的“关节力控”特指关节阻抗控制：控制器仍跟踪关节或末端目标，但允许外力造成一定偏差。
它不是直接下发关节力矩，也不是恒力控制。

## 默认参数

左右臂正式运动均使用以下七轴刚度：

```text
kp = 400 400 400 500 300 200 200
```

拖拽示教录制期间，仅被示教的手臂临时使用低刚度：

```text
kp = 50 50 50 60 30 30 30
```

录制结束后恢复标准 `kp`，控制模式保持为 `3`，不再切回模式 `1`。本次修改不主动写入
`ki` 或 `kv`，因为当前 GDK 文档说明设置接口只应用传入的 `kp`。

## 统一模式入口

`G2Controller` 提供唯一的正式运动准备入口，负责：

1. 读取运动状态并拒绝错误状态。
2. 切换到 `control_mode=3`。
3. 分别为左、右控制组设置七个标准关节阻抗参数。
4. 再次读取状态，确认模式为 `3` 且错误码为零。

模式切换和阻抗设置应具备幂等性。同一运行过程中重复准备运动不会依赖调用者猜测当前模式，
也不会让某一阶段自行切回位控。只读相机、标注、训练和纯状态查询入口不得因为创建控制器而改变机器人状态；
只有明确允许运动的入口才调用运动准备逻辑。

## 运动接口

项目保留现有三类 GDK 运动接口及其用途：

- `joint_control_request()` 继续负责预设位和规划式关节运动，请求在模式 `3` 下执行。
- `move_arm_joint_servo()` 继续负责示教轨迹等高频关节目标流，在模式 `3` 下执行。
- `end_effector_pose_control()` 继续负责视觉伺服、笛卡尔小范围运动和 SpaceMouse 控制，
  在模式 `3` 下执行。

本次不把笛卡尔目标离线转换为关节轨迹。GDK 已声明末端位姿接口支持模式 `3`，保留该接口可以避免
引入新的 IK 分支、奇异点行为和轨迹差异。

所有当前硬编码要求 `control_mode=1` 的正式运动检查改为要求健康的 `control_mode=3`。
错误信息必须明确报告实际模式和错误码，不能静默回落到模式 `1`。

## 流程行为

### 完整流程

主流程获得运动许可后、执行第一个运动动作前统一进入模式 `3` 并设置双臂标准刚度。
后续阶段不得自行切回模式 `1`。阶段失败、操作者中断和正常结束不自动改变为位控；机器人保留
模式 `3` 和标准刚度，以满足“以后默认控制方式也是关节阻抗”的要求。

### 示教录制与回放

录制开始时为所选单臂设置低刚度，并以当前关节角作为参考目标，操作者随后拖动该手臂。
录制结束或异常退出时，为该臂恢复标准刚度并保持模式 `3`。

回放不使用低刚度，继续按照轨迹时间以 `move_arm_joint_servo()` 发送七轴绝对目标，使用标准刚度。
左右臂控制组和七轴顺序保持现有约定。

### SpaceMouse

SpaceMouse 启动准备从“确保模式 1”改为“确保模式 3 并设置标准刚度”。末端增量控制逻辑、
坐标映射、频率和命令有效期保持不变。

## 明确保留的专用工具

专门验证其他模式的诊断程序不纳入默认正式运动链路：

- 显式切回位置控制的工具仍可用于故障恢复和对照测试。
- 笛卡尔阻抗演示仍使用模式 `2`，否则它不再是笛卡尔阻抗演示。

这些工具必须在名称和终端输出中明确其专用模式，不能被完整流程隐式调用。

## 错误处理

- 模式切换失败、阻抗设置失败或状态错误时，在发送任何运动目标前终止当前运动入口。
- 不因模式 `3` 初始化失败而回落到模式 `1`。
- 示教录制清理逻辑即使遇到中断，也应尝试恢复标准刚度；恢复失败需要明确报告。
- 阻抗控制不等于碰撞保护。现有速度、关节限位、超时、轨迹插值和规划碰撞检查保持原义。

## 测试与验证

自动测试覆盖：

1. 正式运动准备将机器人切到模式 `3`，并为左右臂设置正确的七轴 `kp`。
2. 已处于健康模式 `3` 时重复准备仍保持正确状态。
3. 规划关节运动、关节伺服和末端位姿流接受模式 `3`，拒绝错误模式。
4. 示教录制使用低刚度，正常结束和异常退出均恢复标准刚度但不切回模式 `1`。
5. 示教回放在标准关节阻抗下发送正确的单臂七维目标。
6. SpaceMouse 启动进入模式 `3`。
7. 只读入口不改变控制模式。

实机验证分阶段执行：先单臂小位移和停止，再验证预设位、SpaceMouse、左手抓取、示教回放，
最后运行双臂完整流程。每一步检查实际模式、跟踪误差、外力柔顺性和停止后的保持行为，不能只以 API
返回成功作为验证依据。
